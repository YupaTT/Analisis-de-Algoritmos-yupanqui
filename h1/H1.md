# H1 — Generación del reporte de ventas

Este mes optimizaré la generación del reporte de ventas: los productos más vendidos en un periodo.
El reporte se filtra por un rango de fechas (`desde`–`hasta`) y, de forma opcional, por sucursal (`sucursalId`).
Lo sufre quien consulta el reporte, que espera la respuesta cada vez que cambia el rango o la sucursal.
El proceso trabaja sobre el detalle de ventas: unas 120.000 líneas por mes y unos 8.000 productos distintos.
La lógica actual, simulada en [reporte_actual.go](reporte_actual.go), hace tres pasos:
1) recorre todas las líneas para quedarse con las del rango de fechas y la sucursal pedida;
2) por cada línea filtrada busca su producto uno por uno en la lista de totales y suma cantidad y monto;
3) ordena los totales de más a menos vendido con inserción.
Cada consulta repite los tres pasos desde cero, aunque los datos no hayan cambiado.
Medido con datos generados ([mediciones.txt](mediciones.txt)): 0,23 s el reporte de un mes y 2,6 s el de un año.
Al duplicar las líneas, el tiempo casi se duplica: el recorrido completo domina en estos tamaños.
La [muestra](ventas_muestra.csv) tiene 20 líneas con el formato del detalle de venta; los valores son simulados.
El objetivo es bajar ese tiempo sin cambiar el resultado: mismos productos, mismas cantidades, mismo orden.

**Estimación de O:** O(n + m·p + p²), con n líneas, m líneas filtradas y p productos distintos:
un recorrido completo, una búsqueda lineal de producto por cada línea filtrada y un ordenamiento cuadrático.

## Cómo correrlo

```bash
go run h1/reporte_actual.go                # reportes con la muestra (todas las sucursales y la sucursal 1)
go run h1/reporte_actual.go -n 120000      # medición: 1 calentamiento, 3 corridas y promedio
```
